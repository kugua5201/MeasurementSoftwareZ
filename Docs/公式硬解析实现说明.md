# 公式硬解析实现说明

本文档说明 `Services/Measurements/MeasurementFormulaEvaluator.cs` 中公式解析器的实现思路，重点解释“硬解析”是什么、为什么这样实现，以及每一层 `ParseXxx` 是如何协作完成计算的。

## 1. 什么叫“硬解析”

这里说的“硬解析”，指的是：

- 不先把整段公式拆成独立 Token 列表
- 不额外建立一套词法分析器对象模型
- 直接拿原始字符串逐字符读取
- 用一个当前位置指针 `_position` 从左到右推进
- 一边读取，一边判断当前应该按哪一层语法规则处理

也就是说，这个解析器的核心状态其实很少：

- `_expression`：整段原始公式字符串
- `_variables`：外部传入的变量表
- `_position`：当前解析到的字符位置

例如公式：

```text
round((X1 + X2) / 2, 3)
```

解析器不会先生成类似下面这样的 token 队列：

```text
round ( ( X1 + X2 ) / 2 , 3 )
```

而是直接从第 1 个字符开始：

1. 读到 `r`，识别为标识符开头
2. 往后读到 `round`
3. 看到后面是 `(`，判断它是函数调用
4. 进入参数解析
5. 参数内部再次递归解析 `(X1 + X2) / 2`

所以它是“边读边算、边读边递归”的方式。

---

## 2. 总体实现方式：递归下降解析

当前解析器本质上是一个**递归下降解析器**。

它把表达式按运算符优先级拆成多层，每一层只负责自己那一层的运算符。

调用顺序如下：

1. `ParseExpression()`
2. `ParseLogicalOr()`
3. `ParseLogicalAnd()`
4. `ParseBitwiseOr()`
5. `ParseBitwiseAnd()`
6. `ParseShift()`
7. `ParseAddSubtract()`
8. `ParseTerm()`
9. `ParsePower()`
10. `ParseUnary()`
11. `ParsePrimary()`

可以把它理解成：

- 越靠上，优先级越低，负责“包住”更大的表达式
- 越靠下，优先级越高，负责更贴近单个值的部分

### 当前优先级从低到高

1. `||`
2. `&&`
3. `|`
4. `&`
5. `<<`、`>>`
6. `+`、`-`
7. `*`、`/`、`%`
8. `^`
9. 一元 `+`、`-`、`!`、`~`
10. 括号、数字、变量、常量、函数调用

---

## 3. 为什么这种分层能保证优先级正确

以公式：

```text
1 + 2 * 3
```

为例。

### 解析过程

`ParseExpression()` 最终会进入 `ParseAddSubtract()`。

在 `ParseAddSubtract()` 里：

1. 先调用 `ParseTerm()` 解析左边第一项，得到 `1`
2. 看到后面是 `+`
3. 再调用一次 `ParseTerm()` 去解析右边这一项 `2 * 3`
4. 而 `ParseTerm()` 会优先处理 `*`
5. 所以右边整项先算成 `6`
6. 最后 `1 + 6 = 7`

也就是说：

- `ParseAddSubtract()` 不直接自己解析 `2`
- 它把“右侧一整项”交给更高优先级的 `ParseTerm()`
- 所以乘法天然就比加法先算

这就是递归下降里“靠调用更深一层来体现更高优先级”的核心思想。

---

## 4. 每一层是怎么工作的

## 4.1 ParseExpression

这是总入口。

它本身不做复杂工作，只是统一从最低优先级开始：

- 调用 `ParseLogicalOr()`

这样所有表达式都会按照完整优先级链条往下走。

## 4.2 ParseLogicalOr

负责解析逻辑或：

- `||`

处理方式：

1. 先拿到左值：`ParseLogicalAnd()`
2. 如果后面还有 `||`
3. 就继续解析右值：`ParseLogicalAnd()`
4. 结果用 `IsTrue()` 转逻辑真假
5. 再用 `ToBooleanNumber()` 转回 `1` 或 `0`

例如：

```text
X1 || X2 || X3
```

会被当成连续逻辑或处理。

## 4.3 ParseLogicalAnd

负责解析逻辑与：

- `&&`

逻辑和上面一样，只是优先级比 `||` 更高。

例如：

```text
X1 && X2
```

## 4.4 ParseBitwiseOr

负责解析按位或：

- `|`

这里有一个细节：必须避开 `||`。

所以代码是：

1. 先试探吃掉一个 `|`
2. 如果下一个还是 `|`
3. 说明真实运算符是 `||`
4. 就回退一个字符，让上层 `ParseLogicalOr()` 去处理

真正按位或时，会先把左右值通过 `ToIntegerResult()` 转成整数再做运算。

## 4.5 ParseBitwiseAnd

负责解析按位与：

- `&`

和按位或类似，也需要避开 `&&`。

## 4.6 ParseShift

负责解析移位：

- `<<`
- `>>`

移位本身就是整数语义，所以两边都会先转整数。

例如：

```text
X1 << 2
X2 >> 1
```

## 4.7 ParseAddSubtract

负责解析双目加减：

- `+`
- `-`

注意这里只负责双目，不负责一元正负号。

一元 `-X1` 这种是在 `ParseUnary()` 里处理的。

## 4.8 ParseTerm

负责解析：

- `*`
- `/`
- `%`

同时它会检查：

- 除数不能为 0
- 取模除数不能为 0

例如：

```text
X1 * 2 / X2 % 3
```

## 4.9 ParsePower

负责解析幂运算：

- `^`

这里实现成了**右结合**。

例如：

```text
2 ^ 3 ^ 2
```

按：

```text
2 ^ (3 ^ 2)
```

计算，而不是：

```text
(2 ^ 3) ^ 2
```

这是因为代码里右边再次调用的是 `ParsePower()` 自己。

## 4.10 ParseUnary

负责解析一元运算：

- `+X1`
- `-X1`
- `!X1`
- `~X1`

这些运算都必须在进入基础值之前处理，否则像 `-X1^2` 这种表达式的绑定关系就会混乱。

## 4.11 ParsePrimary

这是最底层，负责解析最基础的值。

它只处理三大类：

1. 括号表达式
2. 数字
3. 标识符

### 括号

如果遇到 `(`：

1. 递归调用 `ParseExpression()`
2. 再强制要求后面必须有 `)`

所以括号里的内容会被当作完整子表达式优先处理。

### 数字

如果当前字符是数字或 `.`，就走 `ParseNumber()`。

### 标识符

如果当前字符是字母或 `_`，就走 `ParseIdentifier()`。

---

## 5. 数字是怎么解析的

`ParseNumber()` 会从当前位置开始，连续读取：

- 数字字符
- 小数点 `.`

然后把这一段子串交给：

- `double.TryParse(..., CultureInfo.InvariantCulture)`

也就是说当前支持的是：

- 十进制整数
- 十进制小数

当前不支持：

- 科学计数法
- 十六进制
- 带符号数字字面量

注意：负号不是数字的一部分，而是由 `ParseUnary()` 单独处理。

例如：

- `123`
- `45.67`

合法。

---

## 6. 标识符、变量、常量、函数是怎么区分的

`ParseIdentifier()` 会先读取一个完整名字，比如：

- `X1`
- `PI`
- `round`

然后再分情况：

### 情况 1：后面紧跟 `(`

说明它是函数调用。

例如：

```text
round(X1, 2)
```

此时会：

1. 进入参数读取循环
2. 每个参数调用 `ParseExpression()` 单独解析
3. 参数之间用 `,` 分隔
4. 读到 `)` 为止
5. 最后交给 `EvaluateFunction()` 执行

这也是为什么函数参数可以是完整表达式，比如：

```text
max(X1 + X2, round(A, 2), 100)
```

### 情况 2：名字是 `PI`

返回 `Math.PI`。

### 情况 3：名字是 `E`

返回 `Math.E`。

### 情况 4：变量表里存在这个名字

返回 `_variables[name]`。

### 情况 5：以上都不是

直接抛异常：

- `未找到公式变量：xxx`

---

## 7. 函数执行是怎么做的

`EvaluateFunction(name, args)` 做三件事：

1. 检查函数名是否存在于 `Functions`
2. 检查参数个数是否符合 `FunctionArgCounts`
3. 调用对应委托真正执行计算

例如：

- `sin(x)` -> `Math.Sin(args[0])`
- `pow(x, y)` -> `Math.Pow(args[0], args[1])`
- `max(a, b, c)` -> `args.Max()`

如果函数内部计算抛错，比如：

- `sqrt(-1)`
- 非法对数底数

这里会统一包一层 `FormulaEvaluationException`，让上层收到可读错误信息。

---

## 8. 为什么逻辑结果返回 1/0

公式求值整体是数值体系，不是单独的布尔表达式体系。

所以：

- true -> `1`
- false -> `0`

对应方法：

- `IsTrue(double value)`：判断一个数是否为真
- `ToBooleanNumber(bool value)`：把真假映射成 `1/0`

当前规则是：

- 非 0 视为真
- 0 视为假

这样逻辑结果仍然可以参与后续数值运算。

---

## 9. 为什么位运算前要先转整数

位运算本质上只能对整数做，所以解析器统一调用：

- `ToIntegerResult(double value)`

处理规则：

1. 如果是 `NaN` 或 `Infinity`，直接报错
2. 否则先 `Math.Truncate(value)` 截断小数部分
3. 再转成 `long`

例如：

- `5.8 & 3.2`

实际会按：

- `5 & 3`

处理。

---

## 10. 为什么要有 Match / MatchString / Expect

这几个方法是“硬解析”的基础动作。

## 10.1 Match(char ch)

作用：

- 如果当前位置字符等于 `ch`
- 就消费掉这个字符，`_position++`
- 返回 `true`
- 否则不动，返回 `false`

适合处理：

- `+`
- `-`
- `(`
- `)`
- `,`

## 10.2 MatchString(string text)

作用：

- 检查当前位置开始是不是某个固定字符串
- 如果是就整体消费掉

适合处理：

- `||`
- `&&`
- `<<`
- `>>`

## 10.3 Expect(char expected)

作用：

- 强制要求当前位置必须是某个字符
- 如果不是，就直接抛异常

常用于：

- 读完括号里的表达式后，要求必须有 `)`
- 读完函数参数后，要求必须正确闭合

---

## 11. 为什么最后要 EnsureCompleted

表达式就算前面算出了值，也不代表整个字符串都合法。

例如：

```text
1 + 2 abc
```

前半部分 `1 + 2` 可以算出 `3`，但后面的 `abc` 明显是垃圾内容。

所以在 `TryEvaluate()` 里，`ParseExpression()` 完成之后还要调用：

- `EnsureCompleted()`

它会：

1. 跳过空白字符
2. 检查是否已经到达字符串末尾
3. 如果没有到末尾，说明还有未识别片段
4. 直接报错

这样能避免“部分解析成功但整体公式其实非法”的情况。

---

## 12. 结合例子看完整流程

公式：

```text
round((X1 + X2) / 2, 3)
```

大致流程如下：

1. `ParseExpression()` 进入总入口
2. 一路下钻到 `ParsePrimary()`
3. 读到 `round`，进入 `ParseIdentifier()`
4. 发现后面有 `(`，判定为函数调用
5. 进入参数解析
6. 第一个参数是 `((X1 + X2) / 2)` 这个完整表达式
7. 参数内部又会递归进入整套优先级解析流程
8. 第二个参数是数字 `3`
9. 两个参数解析完成后调用 `EvaluateFunction("round", args)`
10. 得到最终结果
11. `EnsureCompleted()` 确认字符串已经全部解析完毕

---

## 13. 当前实现的特点

优点：

- 结构直观，优先级一眼能对应到方法层级
- 不依赖复杂解析框架，维护成本低
- 出错位置和错误信息比较直接
- 适合当前这种“轻量公式计算”场景

限制：

- 当前数字解析较简化，不支持科学计数法
- 目前没有比较运算符，如 `>`、`<`、`==`
- 语法扩展时需要手动插入新的优先级层
- 由于是手写硬解析，新增运算符时要特别注意和现有符号冲突，例如 `|` 与 `||`

---

## 14. 看源码时建议重点关注的顺序

建议按下面顺序阅读：

1. `TryEvaluate()`：看入口和错误处理
2. `ParseExpression()`：看总入口
3. `ParseLogicalOr()` 到 `ParsePrimary()`：看优先级层级
4. `ParseIdentifier()`：看函数、常量、变量的分流
5. `EvaluateFunction()`：看函数执行
6. `Match` / `MatchString` / `Expect`：看底层字符消费逻辑
7. `EnsureCompleted()`：看最终合法性校验

这样会最容易看懂整个硬解析是怎么串起来的。
